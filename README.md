# JobApplyScheduler

一个面向 Boss 直聘的求职投递调度器，采用“浏览器脚本 + 本地 Python 后端”的组合方式。

当前主线已经收敛为：
- 单简历
- 单方向投递
- 规则筛选岗位
- 固定打招呼
- 工作日分时投递
- HR 明确索要时才自动发送一次简历

它不是多招聘平台框架，不是自动聊天助手，也不是招聘 SaaS。

## 现在能做什么

- 在 Boss 直聘岗位列表里按 `tags` 顺序轮换搜索关键词
- 对岗位做本地规则打分，不依赖任何大模型
- 达到阈值后等到当前小时的下一个随机时点，再执行一次固定打招呼流程
- HR 明确索要简历时自动发送一次附件简历，并只回复一次“发给您了哈”
- 遇到超时、详情异常、打招呼异常时自动恢复

## 项目结构

- `main.py`：FastAPI 后端入口，只有 `/client-config` 和 `/get-job-score` 两个接口
- `core.py`：岗位规则评分主逻辑
- `config.py`：配置加载与岗位评分配置
- `web_script.js`：Boss 页面 Tampermonkey 脚本（搜索、小时调度、打招呼、简历请求判断）
- `user_config.example.json`：用户配置模板
- `start_backend.bat`：Windows 一键启动后端

## 快速开始

### 1. 安装依赖

在项目根目录创建独立虚拟环境，并始终使用该环境安装依赖：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果 Windows 没有 `py` 命令，也可以用已安装 Python 的完整路径创建，例如：

```powershell
& "D:\Python\Python 3.13.4\python.exe" -m venv .venv
```

### 2. 准备用户配置

```bash
cp user_config.example.json user_config.json
```

首次最少只需要改这些字段：
- `introduce`：固定打招呼语
- `tags`：搜索关键词列表
- `frontend.resumeIndex`：发第几份简历，从 0 开始
- `frontend.thread`：投递阈值
- `frontend.resumeScanTimeout`：简历请求工作页最长等待时间，默认 120 秒
- `schedule.jobsPerRound`：每个小时批次最多读取并评分的未处理 JD 数，默认 50
- `scoring.max_min_salary_k`：允许的最高起薪，默认 25K；岗位薪资区间下限高于该值时直接跳过

### 3. 启动后端

```powershell
.\.venv\Scripts\python.exe main.py
```

Windows 下也可以直接双击：

```text
start_backend.bat
```

脚本固定使用项目 `.venv\Scripts\python.exe`，不会调用全局 Python。环境不存在或依赖不完整时，会直接显示对应的创建或安装命令。

### 4. 部署浏览器脚本

把 `web_script.js` 内容粘贴到 Tampermonkey 中，然后打开 Boss 直聘页面即可。

前端启动时只请求后端 `/client-config`，统一读取 `introduce`、`tags`、`frontend` 和 `schedule`；请求失败会在页面日志中提示并停止，不做旧接口回退。

首次保存油猴脚本时需要允许它访问 `127.0.0.1`，否则无法调用本地评分接口。程序每个小时最多读取 50 个未处理 JD；这只是单轮扫描量，不是投递数量或全天上限。

## 工作时间与调度规则

- `schedule.weekdays`：工作日，默认 `[1, 2, 3, 4, 5]`，对应周一至周五
- `schedule.startHour` / `endHour`：执行窗口，默认 9 到 18，即 `09:00 <= 当前时间 < 18:00`
- `schedule.jobsPerRound`：每轮最多扫描 50 个未处理 JD；页面刷新或程序重启后，内存去重记录会重置
- `schedule.testIntervalSeconds`：固定间隔测试开关，当前为 10 秒；设为 0 后恢复正常小时策略
- `schedule.strategies`：允许程序随机选择的小时策略，默认启用以下 5 种
- `balanced`：均匀分散在整个小时
- `front_loaded`：前半小时更密，随后逐渐拉长间隔
- `back_loaded`：前半小时较疏，后半小时逐渐加密
- `two_waves`：在小时前段和后段形成两个分散波段
- `mixed_cadence`：穿插 10/20/30/45 秒短间隔与数分钟长间隔
- 每个可执行小时只启动一轮，依次执行“搜索与预加载 → 逐份处理 JD → 简历请求扫描”
- 预加载阶段只收集最多 50 个未处理岗位链接，不集中打开详情页，也不提前评分
- 程序按本轮候选岗位数生成同等数量的有序时点，并随机选择一种启用策略
- 一个时点最多处理一个 JD：读取详情、评分，合格后立即打招呼；不合格或处理失败则等待下一个时点
- 不建立合格岗位队列，不在评分结束后集中投递，也不对失败岗位进行集中重试
- 因上一份处理过久而错过的时点直接作废；该时点对应的 JD 不会被读取或标记为已处理，也不会补发追赶
- 本轮所有岗位时点处理完成后立即扫描一次简历请求，收到工作页完成回执后才允许进入下一轮
- 简历请求工作页被浏览器拦截或超过 `frontend.resumeScanTimeout` 未完成时，本轮记为失败并结束，不自动重试
- 首轮在可执行时段内立即开始；以后每轮完成后等待下一个整点，不补跑错过的小时，也不连续启动下一轮
- 离开工作时间后不再发送本轮剩余的打招呼消息
- 非工作时间自动等待到下一个工作日 09:00
- 页面日志面板提供“开始/结束”按钮；结束会通知详情、打招呼和简历回复工作页停止，后端服务保持运行
- 调度计划与 JD 去重记录只保存在当前脚本内存中，不使用数据库持久化

当前配置启用了固定 10 秒测试模式，会绕过工作日和工作时间限制，并每隔 10 秒处理一个 JD；评分合格后立即打招呼。一轮完成后仍等待下一个小时，不会反复扫描。测试完成后将 `testIntervalSeconds` 设为 0，即可按工作日 09:00-18:00 的随机小时策略运行。

```text

------------------------------------------------
开始本轮第 4/50 个岗位轮询

开始计算职位 [AI 应用工程师] 的匹配度
```

## 页面角色与停止控制

- 搜索页是唯一控制页，负责开始、结束、调度、评分和共享日志
- 程序自动打开的详情页、打招呼页和简历回复页都是只读工作页；切换到这些标签页查看不会打断任务，页面内的人工点击、输入、滚动和导航会被拦截
- 每个工作页绑定独立任务编号；同一页面刷新或重复加载不会再次执行已经领取的任务
- 搜索页点击“结束”后会广播停止信号，工作页在切换联系人、选择简历、填写文本和点击发送前都会再次检查停止状态
- 自己手动打开的消息页不属于自动化流程，脚本不会添加控件、修改页面状态或暂停自动工作页；人工操作与自动回复偶尔重叠时，两边各自继续执行
- 搜索页保留最近 200 条共享日志，自动工作页只显示当前页面的执行状态

首次替换为新版油猴脚本时，先关闭旧脚本已经打开的详情页和消息页，再从搜索页点击“开始”。之后自动工作页可以正常切换查看，人工回复直接单独打开一个普通消息页即可。

## 简历请求规则

- 只读取当前会话最新一条 HR 文本，不分析完整上下文，不调用任何模型
- Boss 内置“索要附件简历”请求卡片只有在它是当前会话最新活动时才视为明确请求
- “你好”“方便聊聊吗”“介绍一下自己”等普通消息不发送简历
- “不用发简历”“不需要简历”“简历不匹配”“暂不考虑”等消息不发送简历
- “发一份简历”“简历发我一下”“请发送简历”“麻烦把简历发过来”等明确表达才发送
- 否定规则优先于请求规则
- 简历索引固定使用 `frontend.resumeIndex`，不重新请求岗位评分
- 发送成功后只回复一次“发给您了哈”，之后该会话不再执行任何自动处理
- 聊天记录出现“点击预览附件简历”后，该会话永久跳过自动处理

## 配置说明

所有用户差异化内容集中维护在 `user_config.json`：

- `introduce`：固定打招呼语
- `tags`：搜索关键词，按顺序轮换
- `schedule`：工作时间、单轮扫描量与投递节奏
- `frontend`：浏览器端运行参数（`resumeIndex`、`thread` 等）
- `backend`：后端评分延迟参数（`job_score_delay_base_ms`、`job_score_delay_jitter_ms`）
- `scoring`：岗位评分关键词规则（标题强负向 / 弱负向 / 强匹配 / 中匹配，正文正向 / 辅助 / 负向）

## 默认岗位方向

默认搜索词与评分规则面向算法工程师、大模型工程师、AI 应用工程师、机器学习工程师、NLP、Agent 和 RAG 岗位：

- 大模型算法、LLM、Agent、RAG、NLP、机器学习、模型微调等明确岗位标题直接获得较高基础分
- 泛化的“算法工程师”只获得中等基础分，需要 JD 命中 PyTorch、LightGBM、XGBoost、RAG、微调、评测等能力后再加分
- 金融 AI、金融大模型、财报和资本市场相关场景在技术匹配的基础上获得领域加分
- 计算机视觉、自动驾驶、机器人、嵌入式、春招、秋招、校招、应届生、销售、运营等明显偏离方向直接拦截
- 机器人、具身智能、嵌入式只在 JD 正文出现时按负向领域扣分；校招和应届生词在正文出现时直接跳过
- Java、前端、推荐广告算法、运维等非主要方向采用扣分，不会影响匹配的大模型和 Python 后端岗位
- 薪资先做确定性过滤：`25-40K`允许继续评分，`30-50K`因最低薪资超过 25K 直接拦截；`面议`等无法确认下限的格式不做薪资拦截
